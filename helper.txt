Обновление сервера через флешку (E:\erp_project) + git — памятка

Смысл схемы: исходный код (бэкенд/фронтенд) хранится на флешке, а не на
диске сервера — флешку можно унести с собой. Флешка нужна ТОЛЬКО в момент
сборки образов (docker compose build) — код "запекается" внутрь Docker-
образа (Dockerfile делает COPY . .), и после сборки сам образ живёт внутри
Docker на диске C:, флешка ему больше не нужна.

Рабочие конфиги (.env, nginx.conf, dnsmasq.conf, hardware_id.txt,
docker-compose.yml с тегами image:) остаются ТОЛЬКО в C:\ERP — контейнеры
запускаются оттуда и работают уже без флешки вообще.


КАЖДЫЙ РАЗ, когда нужно обновить сервер новым кодом:

1. Вставить флешку (буква диска закреплена как E: за этим конкретным
   накопителем — должна подхватываться сама).

2. Обновить код:
   cd E:\erp_project
   git pull

3. Собрать образы (только тут нужна флешка):
   docker compose build backend nginx

4. Вынуть флешку — дальше она не нужна.

5. Применить на сервере (из совсем другой папки, C:\ERP, где лежат все
   боевые конфиги):
   cd C:\ERP
   .\start.ps1

   (start.ps1 сам обновляет hardware_id.txt и делает docker compose up -d —
   подхватит образы, только что собранные на шаге 3, по тем же тегам
   my_erp-backend:latest / my_erp-nginx:latest)


ГДЕ МОЖНО МЕНЯТЬ КОД — на dev-машине И на сервере (в E:\erp_project),
механика одинаковая в обоих местах:

Вариант А — правки на dev-машине (как обычно):
  1. git pull (на всякий случай)
  2. Правите код
  3. git add / git commit / git push
  4. На сервере: вставили флешку -> cd E:\erp_project -> git pull
  5. docker compose build backend nginx
  6. Вынули флешку -> cd C:\ERP -> .\start.ps1

Вариант Б — правки прямо на сервере (в E:\erp_project):
  git pull -> правите код -> git add/commit/push -> docker compose build
  backend nginx -> вынули флешку -> cd C:\ERP -> .\start.ps1
  (то же самое, просто редактирование происходит на другой машине)

ГЛАВНОЕ ПРАВИЛО, раз мест для правок теперь два: ВСЕГДА делать git pull
ПЕРЕД тем, как начать что-то менять — неважно, на dev-машине или на
сервере. Если забыть и поменять одно и то же место в коде в обоих местах
не синхронизируясь — при следующем push/pull будет конфликт, придётся
разруливать вручную (штатная ситуация в git, просто внимательно прочитать,
что предлагает разрешить, и выбрать правильную версию).


РАЗОВЫЕ НАСТРОЙКИ, которые уже сделаны (для справки, если придётся
переустанавливать/переносить):

- Git установлен на сервере (см. Git-2.49.0-64-bit.exe на рабочем столе).

- git identity настроена (нужна, чтобы делать git commit прямо на сервере,
  иначе "fatal: unable to auto-detect email address"):
  git config --global user.email "anvar7235@gmail.com"
  git config --global user.name "Anvar"

- Диск E: (флешка) — exFAT, git ругается на "dubious ownership" (файловая
  система не хранит владельца файлов) — один раз исправлено командой:
  git config --global --add safe.directory E:/erp_project

- Буква E: закреплена именно за этой флешкой Windows (хранится в реестре
  по ID накопителя). Слетит только если в тот же порт воткнуть другую
  флешку, пока эта вынута — тогда та может перехватить букву E:.

- docker-compose.yml (в репозитории) у backend и nginx одновременно
  прописаны и build:, и image: (my_erp-backend:latest / my_erp-nginx:latest)
  — это важно: тег образа тогда не зависит от того, как называется папка,
  из которой собирали (E:\erp_project или что угодно другое). Без явного
  image: Docker Compose сам придумывает тег по имени папки, и тогда сборка
  с флешки и работающий C:\ERP оказались бы как бы про разные образы.

- .env / dnsmasq.conf / hardware_id.txt на флешку копировать НЕ нужно —
  Dockerfile их не использует на этапе сборки, они нужны только для
  запуска, а запуск всегда идёт из C:\ERP.
